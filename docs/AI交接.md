## 0. 三十秒速览

RoboMaster 飞镖飞控。两块板子：

| | 芯片 | 语言 | 关键文件 | 编码 |
|---|---|---|---|---|
| 下位机 | STM32F103C8T6 | C（Keil MDK） | `rm_dart/MDK-ARM/Control_Task.c`<br>`rm_dart/MDK-ARM/USER/TASK/Inc/ctl_task.h` | **GBK + CRLF** |
| 上位机 | OpenMV | MicroPython | `main.py` | UTF-8 + LF |

飞行流程：发射 → 上升段（pitch 补偿 + yaw 自稳）→ 下降段（视觉追踪 / 脱锁滑翔）→ 落地。
下降段只有 **1.3~1.8 s**，这是所有控制问题的硬约束。

**动手前必读 `AGENTS.md`**：里面写了编码规范、禁改项、提交前必跑的命令。
本文档只补充「历史结论」和「数据怎么读」。

## 1. 数据在哪，怎么读（最容易踩雷的一节）

飞行数据在 `内录/11.15/`（不入库），`telem_*.csv` + `rec_*.mjpeg`。
CSV 列：

```
t_ms,frame,mode,state,flags,gx_dps,gy_dps,gz_dps,pitch_deg,yaw_deg,roll_deg,
out_pitch_deg,out_yaw_deg,out_roll_deg,los_yaw_deg,los_pitch_deg,
s1_deg,s2_deg,s3_deg,s4_deg
```

### 1.1 `out_yaw_deg` 在不同分支含义完全不同 —— 这是最大的坑

| 分支 | `out_yaw_deg` 的含义 | 量级 |
|---|---|---|
| 视觉追踪帧 | `yaw_command`（相对光轴的指令角） | 0~15° |
| 滑翔 / 脱锁帧 | `launch_yaw_deg`（**绝对航向**） | ±180° |
| 目标丢失锁存帧 | **不更新**，保持上一帧的值 | 不定 |

**正确过滤方式**：先取上升段 `out_yaw_deg` 的众数作为 `launch_yaw`，
然后视觉帧 = `state==5 and (flags & 0x02) and abs(outY - launch_yaw) > 0.05`。

**不要用 `abs(outY) < 20` 当过滤器。** 11.15 有 **19/37 发的 `launch_yaw` 落在 ±20° 内**
（00015 是 1.4°、00026 是 1.3°、00024 是 0.0°），滑翔帧会被当成视觉指令混进来，
回归 R² 直接从 0.96 掉到 0.1 以下，结论全错。我踩过这个坑，写进了 7.5.6。

### 1.2 `los_yaw_deg` 列不是控制器用的那个值

```c
los_yaw_deg_out = wrap_180(yaw_deg - debug_ref_yaw_deg) + vision.los_yaw_deg;
```

所以 `los_yaw_deg - yaw_deg = los_rel - ref`，**多了一个未知常数 `ref`**。
只有它的**变化量**有意义。真正的指令是视觉帧的 `out_yaw_deg`。

### 1.3 其它三个坑

- **同一 `t_ms` 可能有 2 行** → 必须先按 `t_ms` 去重，否则回归权重会偏。
- **`state=8`（LANDED）之后舵面冻结**，不是实时值，统计要剔除。
- **舵面反解**：`p/y/r = ((s1±s2±s3±s4))/4`，0.09 °/µs。但
  `DART_SERVO_MAX_STEP_US = 30` 会让四路各自限幅，大机动段反解失真，要剔除
  （判据：相邻帧 `|ΔyCh| > 6°`）。

### 1.4 录像：帧率由「压缩后帧大小」决定

**一条实测规律**（11.15 全部 36 个录像）：

```text
单帧耗时 ≈ 37 ms（snapshot 25 + 识别/叠加/串口 18） + 5~7 ms × 帧大小(KB)
```

| 场景 | KB/帧 | fps |
|---|---:|---:|
| 地面静态画面（QVGA） | 5.9 | **20.7** |
| 飞行，画面干净（QVGA） | 8.0 | 19.2 |
| 飞行，天空+地面+树（QVGA） | 14.6 | **4.4~7.3** |
| 飞行，池化 160×120 | 5.4 | **16~20** |

**地面测试验证不了录像链路**——画面静态，帧小 2.5 倍，正好落在安全区。
要验证必须让画面动起来（对着窗外/复杂场景晃），或者直接看「平均帧大小」：
**> 12 KB 必出问题**（`Compression Failed!` + 掉帧）。

`RECORD_POOL_DIV = 2` 就是为这个加的，00028~00039 十二发全部 16~20 fps，没有一次失败。
想回 QVGA 的话，带宽上限决定了只能 5~7 fps，降 `RECORD_JPEG_QUALITY` 到 30~40 能到 10~12 fps。

**两个坑**：

1. `rec_*.mjpeg` 的 **AVI 头帧率是错的**（写死 13.8 fps），播放器会快放。
   做时间对齐要按帧号对遥测，别信播放器时长。
2. 写失败时 `update_recording()` 会 `os.remove()` 删掉残片再降级 `.bin`，
   所以**「目录里没有坏文件」不等于「没失败过」**。只能看 `record_err.txt`。

## 3. 已经确认的结论（按证据强度排序）

### 3.1 实测确认（有数据/录像支撑）

**① yaw 轴整体反向，全系统只有一个符号。**
IMU 的 pitch/roll 互换且带负号（`DART_SWAP_INS_PITCH_ROLL = 1`），
INS 的 yaw 轴与机体反向：`yaw_ins = −ψ`、`gz = −ψ̇`。相机是正向安装的。
录像 `rec_00013` 实测相邻帧 `ΔX/Δyaw = +1.08 / +0.79`（正常相机应为 −1）。
**现在 `DART_CAMERA_YAW_SIGN = −1` 是唯一的转换点**，输出端没有任何视觉专用符号。
台架若发现 yaw 朝反方向转，**只改这一个宏**。

**② 焦距必须是 480。**
`READOUT_ROI` 改成 `(0,0,1280,960)` 后 `IOCTL_SET_READOUT_WINDOW` 真正生效，
视场从 18.9° 翻到 36.9°。`f_out = 1921 × 320 / W`，W=1280 → 480。
两路独立实测：录像法 8.92 px/度 → f=511；遥测法 `d(相对LOS)/d(yaw) = −0.50` → f=480。
**改 `READOUT_ROI` 必须同步改焦距**，否则视觉环增益整体错一个倍数。

**③ yaw 回路是「延迟决定的极限环」，不是单纯增益问题。**
- 舵面 → 角速率：**200~260 ms**（互相关峰值，corr −0.61~−0.97）
- 相机（曝光 + 中值滤波 + 串口）：**100~130 ms**（MED_WIN=5 时；2026-11-18 改 3 帧后约 80~100 ms）
- 合计 **330 ms**（改 MED_WIN 后 **280 ms**），对应振荡频率 `1/(2×0.33) ≈ 1.5 Hz`，实测周期 **0.65 s**，完全吻合。

**④ 11.15 全部架次的视觉 yaw 参数：KP 一直 20，KD 只有 3.3 / 1.7 两档。**

| 组 | 架次 | KD | gz 峰 | yaw 行程 | 穿中 gz |
|---|---|---:|---:|---:|---:|
| A | 13-17, 24 | **3.3** | 30 | 8.0° | 11 |
| B | 20, 25-27, 30-35, 38, 39 | **1.7** | 62 | 13.6° | 33 |

**KD 砍半 → 所有指标恶化一倍。** 切换点：13-17 A → 20 B → 24 A → 25~39 B，至少 3 次。
（00001~00012 飞行时视觉没亮绿灯，未真正锁定，不计入。）

**⑤ 上升段阶段 2 曾经一次都没执行，已修。**
`ascent_pitch_done` 原来只看 `pitch >= STOP`，发射后低头穿过 `[23°, 30°)` 区间时
同一帧就锁存，阶段 2 被跳过。00005~00014 阶段 2 帧数为 0，整个上升段俯仰通道恒 0。
修法：新增 `ascent_pitch_below_stop`，只有「到过停止角以下又被抬回」才锁存。

**⑥ `Compression Failed!` 是 `fb_alloc` 不足，不是 MicroPython 堆。**
`gc.collect()` 重试对它无效（日志里一条 `retry` 都没有）。22 段录像里 mjpeg 只成功 2 段。
对策：`RECORD_POOL_DIV = 2`（录像前 `mean_pool(2,2)` 降到 160×120），
编码 scratch 从 150 KB 降到 38 KB。

### 3.2 仿真确认（模型能复现实测）

一阶对象 + 双段延迟模型：`τ·dr/dt + r = −G·u(t−Ts)`，`G=3.5~5.0`、`τ=0.1`、
`Ts=0.20`、`Tc=0.13`。

| 配置 | 穿越中心时 gz | 收敛 |
|---|---|---:|
| 20/2.0（**当前**） | 47 → −55 → 71 → −92（发散） | **不收敛** |
| 20/3.0（只加 KD） | 35 | 5.5 s |
| 12/2.0（只降 KP） | 11 | 1.21 s |
| **12/3.0** | **0** | **0.77 s** |
| **10/3.0** | 4 | 0.57 s |

实测 00039 三次穿越中心的 gz 是 **26 / −41 / +69**，与 20/2.0 的仿真序列同型同周期。
**模型可信。**

### 3.3 推断（有数据但未闭环）

- **pitch 也在摆，而且比 yaw 更凶**：`gy` 峰值 79~110 °/s、周期 0.21~0.28 s。
  只是它的设定值从 0 一路压到 −45°，摆动藏在斜坡里看不出来。
  **「yaw 该学 pitch」是误解，两轴是同一个病。**
- 横滚偏置 × 俯仰角速度 → 陀螺看不到的航向漂移：
  `ψ̇ = (r + θ̇·sinφ)/(cosθ·cosφ)`，00003/00005 耦合峰值 8.9/7.1 °/s、积分 −3.4/−3.2°。
  根因是 `DART_ROLL_KI = 0`（现已改 8.0，**未验证**）。

## 4. 下一步建议（按优先级）

### P0：把视觉 yaw 的 KP 降下来 —— **已改（2026-11-18），待飞验证**

**`KP=20 / KD=2.0` 在 330 ms 延迟下是不稳定的**，这是所有「摆到中间又偏走」的根。

已按建议改为 **`DART_YAW_VISION_KP 20 → 12`，`KD 2.0 → 3.0`**，同时
**`main.py` 的 `MED_WIN 5 → 3`**（相机群延迟 100 → 50 ms，总延迟 330 → 280 ms，
`G·T` 1.25 → 1.06）。编译 0 Error/0 Warning，20 + 5 项测试通过。
等价「角度→期望转速」从 10 /s 降到 4 /s，速率阻尼从 2.0 提到 3.0。

**为什么两个一起改**：11.15 的实测把 D 的作用量化了——同样 KP=20，KD≈3.3 的 8 发
去趋势摆幅 5.2°（3.5~6.7）、KD≈1.7 的 12 发 12.1°（4.3~16.0），周期都在 0.5 s。
周期不变说明 D 不改频率、只改衰减，即它把 `G·T` 的稳定边界往上抬，而 20/3.3 只是
**贴着边界内侧**（离散度仍受当次几何影响）。降 KP 才是把工作点移进边界内。

注意两点：
- **单降 KP 就够**（12/2.0 已收敛），加 KD 只是让它更快（1.21 s → 0.77 s）。
- **单加 KD 不够**（20/3.0 要 5.5 s，20/4.0 在 G=5.5 仍发散）。

下一批数据验证判据：视觉段 yaw **去趋势摆幅 <5°**（11.15 低 D 组 12.1°、高 D 组 5.2°）、**摆动周期 0.38~0.45 s**（原 0.43~0.64 s，周期缩短 = 延迟真的降了）、过中心顶反帧 <10%、对准后回摆 <2°、目标在位率不降。

## 5. 踩过的坑（每条都是花钱买的）

1. **用 `|outY| < 20` 过滤视觉帧** → 19 发的 `launch_yaw` 在 ±20° 内，滑翔帧混进来，R² 掉到 0.1。
2. **拿 `los_yaw_deg - yaw_deg` 当相对视线角** → 差一个未知常数 `ref`，只有变化量有意义。
3. **以为 `gc.collect()` 能救 `Compression Failed!`** → 那是 `fb_alloc`，两套内存。
4. **以为「修完就好了」** → 11.14 那次「修完好一发、又坏、后来全好」的真实原因是重烧 `main.py`
   重启了解释器，不是修复生效。
5. **以为「与开机时长强相关」** → 用遥测首行 `t_ms` 证伪：43.2 s 有成有败，15.9 s 也失败过。
6. **把 yaw 的「输出反向」当成符号 bug** → 实际是 D 项压过 P 项（焦距错一倍把 P 砍半），
   加大 KD 反而更差。判定方法：`yCh = a·cmd + b·gz` 二元回归，看 a、b 的符号和幅值。
7. **以为 pitch 比 yaw 好** → pitch 的 `gy` 摆得更凶，只是被滑翔斜坡掩盖。
8. **闭环遥测算不出被控对象符号** → 控制器会把舵面与响应解耦，`corr(y_us, Δyaw)` 中位 −0.01。
   符号只能靠台架。
9. **仿真里加「速率积分」** → 330 ms 延迟下反向超调 18~24°，直接发散。别加。
10. **加大前视/预测来补偿延迟** → 前视项被 ±3° 卡死；2 Hz 摆动周期 0.5 s，
    预测 0.33 s 等于预测半个周期，会预测到反号。危险。
