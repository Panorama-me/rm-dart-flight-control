## 方案 A（惯性系 yaw KF）效果验证 + RAM 回收（提交 d5fafd6）

### 1. 修复效果量化（合成对照）

用 00014 真实 yaw 轨迹合成**静止目标**（真值 ω=0，gz 峰值 171 °/s，视觉延迟 45 ms），
同一份数据喂新旧链：

| 链 | 斜率 ω/gz | 相关 | ω sd |
|---|---:|---:|---:|
| 旧（像素 EKF rate + 实时 gz） | **+1.00** | 0.80~0.91 | 85~100 °/s |
| 新（惯性系 KF） | **+0.01** | 0.03~0.20 | 3.0~17.6 °/s |

旧链斜率 1.00 = gz 泄漏 100%，坐实"ω 几乎等于机头转速"。

**36 发真实数据回放**：`|corr(ω,gz)|` 0.95 → 0.38，ω sd 14.5 → 9.7。
0.38 **不是残留泄漏**——速率型 PN 稳态就是 gz≈N·ω，闭环物理耦合。
合成实验证明新链泄漏只有 0.01。**不要再往 0 压**，压下去等于削弱跟踪。

### 2. 延迟 30 ms 未实测

飞行数据反推不出（闭环耦合污染），合成校准显示判据在慢转下很钝（Δtrue=45/70 都指向 ~36 ms）。
台架手持数据 gz 只有 ~20 °/s，分辨不出 30 与 45。结论：30 ms 无实测支撑，但泄漏已是 1% 量级。
要精定需台架 40~60 °/s 快转一段。

### 3. 俯仰轴仍是旧链（主要遗留）

`camera_pitch_rate = SIGN*(vision_y_ekf.rate − gy)`，同 yaw 修复前结构。

- `los_pitch_deg` 仍来自像素域 EKF（滞后）
- 前视项 `|0.2s×rate| > 3°` 的帧占比 **中位 90%**（常年顶在限幅上）
- `camera_pitch_rate` 与真实相机角差分相关仅 **0.18**

RAM 现在有余量，加 pitch 缓冲 256 B + KF 30 B 不成问题。

### 4. RAM 清理

| 项 | 改前 | 改后 | 省 |
|---|---:|---:|---:|
| `ucHeap`（FreeRTOS） | 10240 | **6144** | 4096 |
| `Heap_Mem`（Keil 传统堆） | 512 | **0** | 512 |
| `DartControl`（filtered_x/y） | 1132 | **1124** | 8 |
| **合计 RAM** | **19504** | **14888** | **4616** |

余量 976 → **5592 B（27%）**。Code 41724 / RO 2768 / RW 572 / ZI 14316。

- 删 `filtered_x/filtered_y`：只写不读，每 2 ms 两次软浮点 `tanf`（314 B 实现）
- FreeRTOS 堆：3 个 osThreadNew 共约 3.9 kB，原值空置 6 kB；`.ioc` 同步
- `freertos.c` 加 `osThreadNew == NULL → Error_Handler()`，堆不足不再静默
- Keil 传统堆置 0：全工程无 malloc/printf（priority_ui.c 未编译）

**还能省但不建议**：
- `pxReadyTasksLists` 1120 B ← `configMAX_PRIORITIES=56`，降到 32 省 480 B，但改全系统数值优先级
- `Timer_Stack` 1024 + 定时器队列 ~240 B ← `configUSE_TIMERS=0`，CMSIS-RTOS2 可能依赖
- 主栈 `Stack_Mem` 2048：Cortex-M 所有 ISR 跑在 MSP（即主栈），不能动

## 6. MODE 1 的 ω 补做 roll 旋转（提交 5da3fea）

用户发现：速率型 PN 的 ω 没做 roll 旋转，而角度指令做了。

图像轴随滚转旋转：`ω_body_yaw = cosφ·ω_img_x + sinφ·ω_img_y`。
原代码 `rate_cmd = SIGN·N·pn_omega_yaw − gz`，左边相机平面、右边机体轴。

11.20 全批 1337 帧量化：
- `|roll|` 中位 1.0°、p90 2.7°、最大 16.3°（滚转控得住）
- `|ω_pitch|` 中位 **35 °/s**，是 `|ω_yaw|`(6.4) 的 5 倍
- 漏项 `sinφ·ω_pitch`：中位 0.6、p99 7.2 °/s
- 折算舵偏（K·N=24）：中位 10、p90 53、p99 106、**最大 180 µs**（限幅 250）
- **12% 的帧改动 > 50 µs**

改法：`roll_rad/cos/sin` 提前到 PN 之前，旋转后再进 `rate_cmd`。
`vis_rate_dps` 遥测仍在**旋转前**取样，保持与 `los_yaw_deg` 差分同轴系，
`tools/eval_vis_rate.py` 判据口径不变。

编译 0/0，Code 41724 → 41756；测试 21+5。
